# Retracted: pre-bugfix ablation results

The files in this directory were produced **before** a config-forwarding bug was found and fixed in scripts/train.py's build_model() and scripts/evaluate.py's load_model(): the use_gating / use_mixing flags were defined in the training config but never threaded into the decoder block's model constructor, so any run that set either flag to False (i.e. every no_gating and no_mixing ablation run) silently trained/evaluated with **both components fully active** regardless of the flag. Only the no_gating and no_mixing files are affected by this specific bug -- the corresponding k4/k16 slot-count sweep uses the default use_gating=true, use_mixing=true, so that bug does not apply to it, and those files are NOT quarantined here; they live in the main results/ directory and are the same values reported in the paper.

We keep these files rather than deleting them, exactly as the paper does for every other retracted claim: not to use them, but so the record of what was wrong and why is not silently erased. The corrected re-runs, produced after both bugs were fixed, are the ones actually reported in the paper -- see the parent results/ directory and analysis/gsm8k_fixed_results/ for the corrected numbers.
